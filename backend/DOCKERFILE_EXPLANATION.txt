================================================================================
BACKEND DOCKERFILE EXPLANATION
================================================================================

This file explains how the backend Dockerfile works line by line.

================================================================================
LINE-BY-LINE BREAKDOWN
================================================================================

1. FROM node:18-alpine
   ────────────────────
   • FROM = Start from a base image
   • node:18-alpine = Official Node.js version 18 image using Alpine Linux
   • Alpine = Lightweight Linux distribution (~5MB vs ~900MB for full Ubuntu)
   • This is the foundation for your container

2. WORKDIR /app
   ────────────
   • Creates /app directory inside the container
   • Sets it as the current working directory for all following commands
   • Like doing "mkdir /app && cd /app"
   • All your files will be inside /app

3. COPY package.json package-lock.json ./
   ──────────────────────────────────────
   • Copies package.json and package-lock.json from your host machine (Windows) 
     to the container (/app)
   • ./ means "current directory" (which is /app because of WORKDIR)
   • Why copy these first? Docker caching! If these files don't change, 
     Docker reuses the next layer

4. RUN npm install --production
   ─────────────────────────────
   • Runs "npm install" inside the container
   • --production = Only installs dependencies, not devDependencies (smaller image)
   • Downloads and installs all packages from package.json into /app/node_modules
   • This layer is cached if package.json hasn't changed (saves time!)

5. COPY . .
   ────────
   • First "." = Source (everything in backend/ folder on your computer)
   • Second "." = Destination (/app in container)
   • Copies all your code: index.js, controllers/, models/, routes/, etc.
   • Respects .dockerignore = Won't copy node_modules, .env, etc.

6. EXPOSE 5000
   ───────────
   • Documentation only! Tells Docker "this app uses port 5000"
   • Doesn't actually publish the port (that's done in docker-compose.yml)
   • Best practice to document which port your app listens on
   • Your Express server listens on port 5000

7. CMD ["node", "index.js"]
   ────────────────────────
   • CMD = Default command to run when container starts
   • ["node", "index.js"] = Runs "node index.js" (starts your Express server)
   • JSON array format = "exec form" (preferred, doesn't spawn shell)
   • This is equivalent to running "node index.js" in the terminal

================================================================================
BUILD PROCESS FLOW
================================================================================

When you run "docker-compose build backend":

1. FROM node:18-alpine          → Download base Node.js image
2. WORKDIR /app                 → Create /app directory
3. COPY package*.json           → Copy package files
4. RUN npm install              → Install dependencies (cached if no changes)
5. COPY . .                     → Copy your code
6. EXPOSE 5000                  → Document port
7. Image is ready!

When you run "docker-compose up":

8. CMD ["node", "index.js"]     → Start Express server
9. Server listens on port 5000

================================================================================
WHY THIS ORDER MATTERS
================================================================================

✅ GOOD (current order):
   COPY package.json ./
   RUN npm install
   COPY . .

   Benefit: If you change your code but not package.json, Docker reuses 
   the cached "npm install" layer (fast!)

❌ BAD order:
   COPY . .
   RUN npm install

   Problem: Every code change invalidates the cache, so "npm install" 
   runs every time (slow!)

================================================================================
DOCKER LAYERS & CACHING
================================================================================

Each instruction in the Dockerfile creates a "layer". Docker caches these 
layers. If nothing changes, Docker reuses the cached layer (super fast!).

Example:
- You change index.js
- Docker reuses cached layers for: FROM, WORKDIR, COPY package.json, RUN npm install
- Docker only rebuilds: COPY . . and everything after it
- This saves tons of time!

================================================================================
POTENTIAL IMPROVEMENTS
================================================================================

For Development (with hot reload):
──────────────────────────────────
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install  # Install ALL deps including nodemon
COPY . .
EXPOSE 5000
CMD ["npm", "start"]  # Uses nodemon for hot reload

Your current Dockerfile is production-ready and efficient!

================================================================================
KEY CONCEPTS
================================================================================

• Container = Running instance of an image
• Image = Blueprint/template for containers (like a class in programming)
• Layer = Each Dockerfile instruction creates a layer
• Cache = Docker remembers layers to speed up builds
• Alpine = Minimal Linux distribution (small size)
• WORKDIR = Sets the working directory inside container
• COPY = Copies files from host to container
• RUN = Executes commands during build
• CMD = Command to run when container starts
• EXPOSE = Documents which port the app uses
