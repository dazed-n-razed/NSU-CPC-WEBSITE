================================================================================
FRONTEND DOCKERFILE EXPLANATION - MULTI-STAGE BUILD
================================================================================

The frontend Dockerfile uses a TWO-STAGE build which is more advanced and 
optimizes the final image size significantly.

================================================================================
UNDERSTANDING /app IN CONTAINERS
================================================================================

Important Concept:
─────────────────

• Container Name: nsu-cpc-frontend (defined in docker-compose.yml)
• /app: A directory PATH INSIDE the frontend container

Think of it like this:

Your Windows Machine:
C:\Users\shahr\Documents\GitHub\NSU-CPC-WEBSITE\frontend\
├── src/
├── public/
├── package.json
└── ...

↓ Docker copies files to ↓

Frontend Container (nsu-cpc-frontend):
/app/                           ← This is the directory inside the container
├── build/
│   ├── index.html
│   ├── static/
│   └── ...

So:
• Container = The running instance (like a mini virtual computer)
• /app = Just a folder inside that container where your React app lives

Every container has its own isolated filesystem. /app in the frontend 
container is completely separate from /app in the backend container!

Example:

Backend Container (/app):       Frontend Container (/app):
/app/                          /app/
├── node_modules/              └── build/
├── controllers/                   ├── index.html
├── models/                        └── static/
├── index.js
└── ...

They're isolated from each other! 🔒

================================================================================
STAGE 1: BUILD STAGE (TEMPORARY)
================================================================================

FROM node:18-alpine AS builder
─────────────────────────────────
• FROM node:18-alpine = Start with Node.js 18 Alpine base image
• AS builder = Name this stage "builder" so we can reference it later
• This stage is temporary and will be discarded after the build

WORKDIR /app
────────────
• Creates /app directory in the builder container
• Sets it as the working directory
• All commands run inside /app

COPY package.json package-lock.json ./
─────────────────────────────────────
• Copies package files from your frontend folder to container's /app
• Same caching benefit as backend
• If these don't change, Docker reuses the next layer

RUN npm install
───────────────
• Installs ALL dependencies (including dev dependencies)
• Need devDependencies because React needs build tools (webpack, babel, etc.)
• Creates /app/node_modules with all packages
• Note: This installs ~200MB+ of dependencies for building

COPY . .
────────
• Copies all your React source code to /app
• Includes: src/, public/, config files, etc.
• Respects .dockerignore (won't copy node_modules, build folder)

RUN npm run build
─────────────────
• Runs react-scripts build (from package.json)
• COMPILES your React app into optimized static files
• Creates /app/build folder with:
  - Minified JavaScript bundles
  - Optimized CSS
  - HTML files
  - Static assets
• This is production-ready code (~2-5MB typically)

================================================================================
STAGE 2: PRODUCTION STAGE (FINAL)
================================================================================

FROM node:18-alpine
───────────────────
• Starts FRESH! New clean container (discards Stage 1)
• Only keeps what we explicitly copy from Stage 1
• This is why the final image is small

WORKDIR /app
────────────
• Creates /app in this new container
• Sets working directory

RUN npm install -g serve
────────────────────────
• npm install -g = Install globally
• serve = Lightweight static file server (~1MB)
• Used to serve your built React app
• Alternative to Nginx or Apache

COPY --from=builder /app/build ./build
──────────────────────────────────────
• --from=builder = Copy from Stage 1 (the "builder" stage)
• /app/build = Source (built files from Stage 1)
• ./build = Destination in current stage (/app/build)
• ONLY copies the compiled production files, NOT node_modules!
• This is the magic that makes the image small

EXPOSE 3000
───────────
• Documents that the app runs on port 3000
• The serve command will listen on this port

CMD ["serve", "-s", "build", "-l", "3000"]
──────────────────────────────────────────
• serve = Run the serve command
• -s build = Serve files from the build directory as a Single Page App
• -l 3000 = Listen on port 3000
• SPA mode rewrites all routes to index.html (needed for React Router)

================================================================================
COMPLETE BUILD FLOW
================================================================================

STAGE 1 (Builder) - Temporary:
──────────────────────────────
1. FROM node:18-alpine          → Start with Node.js
2. WORKDIR /app                 → Create /app
3. COPY package*.json           → Copy package files
4. RUN npm install              → Install ALL dependencies (~200MB)
5. COPY . .                     → Copy source code
6. RUN npm run build            → Build React app → creates /app/build (~3MB)
   
   [Stage 1 is now complete and will be thrown away]

STAGE 2 (Production) - Final Image:
───────────────────────────────────
7. FROM node:18-alpine          → Start FRESH (new clean container)
8. WORKDIR /app                 → Create /app
9. RUN npm install -g serve     → Install serve (~1MB)
10. COPY --from=builder /app/build  → Copy ONLY the built files from Stage 1
11. Final image = ~50MB (vs ~300MB if we kept everything from Stage 1!)

When container runs:
───────────────────
12. CMD serve -s build -l 3000  → Start web server

================================================================================
WHY MULTI-STAGE BUILD?
================================================================================

Without Multi-Stage Build (Bad):
────────────────────────────────
Final Image Contains:
- Node.js
- All npm packages (~200MB)
- Source code
- Built files
Total: ~300-400MB

❌ HUGE IMAGE SIZE! Slow to download, slow to deploy

With Multi-Stage Build (Good):
──────────────────────────────
Final Image Contains:
- Node.js
- serve package (~1MB)
- Built files only (~3MB)
Total: ~50-60MB

✅ 5x-6x SMALLER IMAGE! Fast to download, fast to deploy

================================================================================
WHAT'S IN EACH STAGE?
================================================================================

Stage 1 (Builder) - Discarded:
──────────────────────────────
/app/
├── node_modules/          (200MB - discarded!)
├── src/                   (discarded!)
├── public/                (discarded!)
├── package.json           (discarded!)
└── build/                 ← Only this is kept!
    ├── index.html
    ├── static/
    │   ├── js/
    │   └── css/
    └── ...

Stage 2 (Production) - Final:
─────────────────────────────
/app/
└── build/                 ← Copied from Stage 1
    ├── index.html
    ├── static/
    │   ├── js/
    │   └── css/
    └── ...

================================================================================
KEY DIFFERENCES: BACKEND VS FRONTEND
================================================================================

Aspect              | Backend           | Frontend
──────────────────────────────────────────────────────────
Stages              | Single stage      | Multi-stage (2 stages)
Build step          | No build needed   | Needs npm run build
Final size          | ~100MB            | ~50MB
Runtime             | node index.js     | serve -s build
Dependencies        | Only prod deps    | Only serve + built files
Source code         | Included          | Excluded (only built files)

================================================================================
ALTERNATIVE APPROACHES
================================================================================

Using Nginx (More common in production):
────────────────────────────────────────
# Build stage
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Production stage
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Benefits: Nginx is faster for serving static files, smaller final image

Development Mode (with hot reload):
───────────────────────────────────
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]  # react-scripts start with hot reload

Benefits: Faster development with automatic reload on code changes

================================================================================
HOW DOCKER COMPOSE USES THIS DOCKERFILE
================================================================================

In docker-compose.yml:

services:
  frontend:
    build:
      context: ./frontend       ← Looks here for Dockerfile
      dockerfile: Dockerfile    ← Uses this file
    container_name: nsu-cpc-frontend
    ports:
      - "3000:3000"             ← Maps port 3000 to your machine
    ...

When you run "docker-compose build frontend":
1. Docker reads frontend/Dockerfile
2. Executes Stage 1 (builds React app)
3. Executes Stage 2 (creates final image)
4. Image is ready to use

When you run "docker-compose up -d":
1. Container starts from the built image
2. CMD runs: serve -s build -l 3000
3. React app serves on http://localhost:3000

================================================================================
ISOLATED FILESYSTEMS
================================================================================

Each container has its own isolated filesystem:

Your Machine         Backend Container       Frontend Container
─────────────────    ─────────────────────   ──────────────────
C:\Users\...         /app                    /app
├── backend/         ├── node_modules/       └── build/
├── frontend/        ├── controllers/            ├── index.html
├── docker-...       ├── models/                 └── static/
└── ...              ├── index.js
                     └── ...

They cannot access each other's /app folders!
They communicate through the Docker network using:
- Backend: http://backend:5000
- Frontend: http://frontend:3000 (or http://localhost:3000 from your machine)
